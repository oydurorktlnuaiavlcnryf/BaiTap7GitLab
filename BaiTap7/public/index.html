Khái niệm CI/CD

🔄

CI — Continuous Integration

Tự động build và test mỗi khi developer push code. Giúp phát hiện lỗi sớm, giảm conflict khi merge.

  • Auto build on every push
  • Run automated tests
  • Code quality checks
🚀

CD — Continuous Deployment

Sau khi CI pass, tự động deploy phiên bản mới lên staging/production. Release nhanh, giảm thủ công.

  • Automatic deployment
  • Zero-downtime releases
  • Rollback capabilities
📊

Pipeline Flow

1
Commit & Push Developer push code lên GitLab repository
→
2
Pipeline Triggered GitLab CI tự động kích hoạt dựa trên .gitlab-ci.yml
→
3
Build Stage Kiểm tra cấu trúc project, compile code
→
4
Test Stage Chạy automated tests, kiểm tra HTML/CSS/JS
→
5
Deploy Stage Deploy lên GitLab Pages, site live tự động
⚙️

GitLab CI/CD Components

Component Mô tả
.gitlab-ci.yml File cấu hình pipeline bằng YAML, đặt ở root của repository. Đây là file duy nhất cần tạo để GitLab CI hoạt động.
Pipeline Tập hợp toàn bộ các jobs được chạy khi trigger. Mỗi push tạo 1 pipeline mới.
Stage Nhóm các jobs chạy song song. Thứ tự stages: .pre → stage1 → stage2 → .post
Job Đơn vị nhỏ nhất trong pipeline, chứa script, stage, và rules.
Runner Server/container thực thi các jobs. GitLab.com cung cấp shared runners miễn phí.
Artifacts Các file được jobs tạo ra, có thể chia sẻ giữa các stages/jobs (VD: build output).
📄

Cấu hình .gitlab-ci.yml

.gitlab-ci.yml 
stages:
  - build
  - test
  - deploy

build:
  stage: build
  script:
    - echo "Building project..."
    - ls -la public/
  artifacts:
    paths:
      - public/

test:
  stage: test
  script:
    - test -f public/index.html
    - test -f public/styles.css
    - test -f public/js/main.js

pages:
  stage: deploy
  script:
    - echo "Deploying to GitLab Pages..."
  artifacts:
    paths:
      - public
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH

Câu hỏi ôn tập

CI (Continuous Integration) tập trung vào việc tự động build và test mỗi khi có thay đổi code. CD (Continuous Deployment) mở rộng CI bằng cách tự động deploy phiên bản đã pass CI lên môi trường staging/production.

Runner là server/container thực thi các jobs trong pipeline. GitLab.com cung cấp shared runners miễn phí, không cần cài đặt riêng. Ngoài ra có thể tự cài đặt self-hosted runners.

Artifacts là các file được jobs tạo ra và có thể chia sẻ giữa các jobs/stages. VD: build output từ job build có thể được job deploy sử dụng.

Không. Stages chạy tuần tự. Nếu 1 stage fail, các stage sau sẽ không được thực thi. Điều này đảm bảo code lỗi không bao giờ được deploy.

Dùng rules trong job:

rules:
  - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH

Bỏ rules hoặc dùng:

rules:
  - if: $CI_COMMIT_BRANCH
